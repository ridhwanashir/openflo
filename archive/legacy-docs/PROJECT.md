## Problem Statement

Indosat's telco data contains application identifiers and traffic records that need to be accurately mapped to:
- **Canonical application names** (standardized, deduplicated)
- **Relevant tags** derived from database attributes
- **Categories** (hierarchical groupings, e.g., `Social Media > Messaging`)
- **Rich descriptions** that can be consumed by an agentic LLM for downstream intelligence tasks

Without a clean mapping layer, application-level analytics, reporting, and AI-driven decisions are unreliable.

---

## Goals & Success Criteria

### Primary Goals
1. **Accurate Mapping**: Every application entry in the source table maps to a verified canonical name
2. **Tag Alignment**: Tags in the database are reconciled and consistent with the mapping
3. **Category Taxonomy**: A clean, hierarchical category system covering all application types in the telco context
4. **LLM-Ready Descriptions**: Descriptions are concise, factual, and provide enough context for an agentic LLM to reason correctly

### Success Criteria
- [ ] 95%+ of app entries have a valid category assigned
- [ ] 0 duplicate canonical names in the mapping table
- [ ] All tags follow a defined controlled vocabulary
- [ ] Descriptions reviewed and approved for LLM consumption
- [ ] BigQuery table and CSV export are kept in sync

## Data Schema (v2 — 2026-03-18)

### CSV / BigQuery Column Definitions

| Column | Type | Description | Required |
|--------|------|-------------|----------|
| `app_name` | STRING | Canonical display name for the application | ✅ |
| `source_app_names_old` | STRING | Original BQ `nio_aggr` identifiers (audit reference, do not alter) | ✅ |
| `sig_app_tags` | STRING | Pipe-separated `#Application` values from the Signature Apps Library — used by the agentic LLM to construct BQ filter queries | ✅ |
| `category` | STRING | L1 category — controlled 11-value vocabulary (see taxonomy) | ✅ |
| `subcategory` | STRING | L2 subcategory — service-type principle (see taxonomy) | ✅ |
| `description` | STRING | 1–2 sentence factual description for LLM consumption. Format: `"[App Name] is a [subcategory] app by [vendor/developer]. It [core functionality and primary use case]."` | ⬜ |

> **Note on `sig_app_tags`**: Generated by `app_mapping_migration.ipynb` via exact → wildcard matching against the Signature Apps Library. For apps not found in the library, the field contains the original `source_app_names_old` values as a best-effort fallback (marked `match_source = fallback_original` in the notebook run).

## Tag Controlled Vocabulary

Tags should be drawn from this vocabulary to ensure consistency:

```
# Traffic characteristics
encrypted, plaintext, high-bandwidth, low-latency, bursty, persistent-connection

# Application behavior
background-sync, real-time, push-notification, periodic-polling, streaming, bulk-transfer

# User demographics (IOH context)
youth-segment, enterprise, mass-market, prepaid, postpaid

# Network layer
tcp, udp, quic, websocket, http2, http3

# Content type
video, audio, text, image, mixed-media, metadata-only

# Business classification
revenue-generating, data-heavy, partner-app, ioh-owned, third-party
```
